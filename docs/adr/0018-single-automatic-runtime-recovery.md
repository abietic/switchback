# Single Automatic Runtime Recovery Per Incident

P0 Supervisor automatically replaces a failed RuntimeInstance at most once for each continuous RuntimeRecoveryIncident caused by confirmed process exit, container loss, heartbeat timeout, ACP connection close, cancellation-grace expiry without a terminal prompt response, or an unconfirmed local Tool cancellation that taints the runtime. `active_quiet`, deadline expiry before cancellation, and uncertain remote side effects are not runtime-recovery failures; remote non-idempotent/unknown effects enter `waiting_user` for reconciliation instead. Recovery preserves WorkerSession, Workspace, WorkingCopy, durable Agent state, Trace cursors, and still-valid scoped ApprovalGrants, while incrementing runtime generation, fencing the old runtime and ChannelEpoch, and issuing fresh SecretLeases. The replacement must safely resume the prior ACP AgentSession, pass control, LiteLLM, ACP, and workspace health checks, and satisfy a configured stability window or durable progress checkpoint before the incident closes. If that single recovery fails, session resume cannot be proven safe, or state consistency is uncertain, WorkerRun and WorkerSession enter `waiting_user`; the platform does not crash-loop or silently create a fresh AgentSession. Cancellation, idle or absolute expiry, authentication, authorization, policy, schema, and protocol failures are not auto-recovery triggers.
