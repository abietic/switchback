# Workspace Is A Multi-Session Multi-Resource Context

A WorkerSession binds to exactly one Workspace, while one Workspace may contain one or more WorkerSessions and zero or more RepositoryCheckouts. Workspace is a durable logical working context rather than a container identity: research, design, document, and Figma-oriented work can begin without a repository, and repositories can be attached later or multiple repositories can be used for one delivery. RuntimeInstance remains the replaceable container or Pod generation that materializes one WorkerSession.

Multiple WorkerSessions never write one authoritative Workspace directory concurrently. Each session owns an isolated WorkingCopy based on a WorkspaceRevision, using per-session Git worktrees or equivalent isolated materialization. A Worker emits a reviewable ChangeSet. WorkspaceApply prepares the complete candidate outside the write lease, then uses a short exclusive lease to revalidate and advance the active WorkspaceRevision. Revision mismatch or content conflicts leave the ChangeSet unapplied for rebase or user resolution. ADR 0027 defines the accepted P0 physical storage, staging, fencing, and finalize transaction.
