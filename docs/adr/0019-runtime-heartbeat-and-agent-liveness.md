# Runtime Heartbeat And Agent Liveness

> Deadline selection and expiry behavior in this ADR are superseded by [ADR 0055](0055-use-a-fixed-agentturn-hard-deadline.md). Heartbeat, liveness evidence, cancellation grace and recovery fencing decisions remain active.

P0 Runtime Shim emits a transport-independent RuntimeHeartbeat every 15 seconds, independently of model streaming and tool execution. The backend uses receive time and monotonic heartbeat sequence: 45 seconds without a valid heartbeat marks RuntimeInstance `suspect`, pauses new command dispatch, and triggers transport, container, Shim, and Agent process checks; 90 seconds without recovery marks it `unhealthy` and may open RuntimeRecoveryIncident. A confirmed process exit or missing container can become unhealthy immediately. The fixed ACP/Codex stack has no safe ping/no-op: Agent unresponsiveness requires process exit, stdio EOF, ACP connection close, or failure to obtain a terminal prompt result within a bounded cancellation grace; absence of model tokens or UI text alone is never sufficient.

`active_quiet` therefore emits only a non-terminal warning while the current AgentTurn's fixed 24-hour hard deadline continues. When that deadline expires, Worker sends ACP cancel and cancels the current Tool/process regardless of interactive, unattended or approval-waiting state; TaskSpec does not select this behavior. Cancellation grace remains a fixed-image Docker spike measurement, starting with a 30-second candidate rather than a frozen production constant. Before a replacement mounts the same WorkingCopy, the control plane must terminate or isolate the old container, revoke its control and secret leases, and acquire an exclusive mount lease; inability to prove write exclusivity escalates to `waiting_user` instead of risking split-brain writes.
