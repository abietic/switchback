# P0 Approval Boundary

Worker may perform ordinary file, command, patch, test, and report operations inside its sandbox without asking for approval. Approval is required when work needs a new external-platform capability, crosses the sandbox boundary, writes production or another protected system, or installs an untrusted Skill. A once or WorkerSession-scoped Grant remains constrained to a concrete capability, target, limits, and expiry. For CodePlatform, ADR 0030 specializes this rule: publishing a branch or performing other non-administrative GitHub operations requires a matching RepositoryAccessGrant, but a valid WorkerSession-scoped Grant authorizes subsequent native `git`/`gh` commands in that repository scope without per-command prompts. Other external systems continue to use their ApprovalGrant/SecretLease policy. While waiting for a decision, the 48-hour idle timer pauses but the 14-day absolute lifetime continues. An explicit user instruction to Assistant to install a Skill counts as an auditable CapabilityInstallGrant. Preinstalled and Evolution-generated Skills do not require a separate user installation prompt, but they still must pass platform policy and capability checks.
